# ANGLER v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ANGLER v4: full-screen descent with a forced "Next question" tap, the Duel mode (2–8 players, pufferfish fuse, two lives), every question at ≥75 sourced answers, and autocorrect that says what it corrected.

**Architecture:** The rules stay in `shared/dive.js` (synced into the Edge Functions); the duel gets its own pure reducer `shared/duel.js` driven by a Supabase Edge Function (`duel`) and Realtime, with a local driver for pass-and-play. The bank grows through `tools/bank/` (cached fetchers for GBIF, FishBase, SeaLifeBase, Wikipedia raw and Wikidata; per-question candidate strategies; a builder that writes sourced entities and tiers them by fame calibrated to each question's existing answers). Past days keep their answer sets through `data/frozen.json`.

**Tech Stack:** vanilla JS (UMD modules), Node 22 (`node --test`), Playwright e2e, Supabase (Postgres, Edge Functions on Deno, Realtime), supabase-js UMD loaded on demand for Realtime.

**Spec:** the pasted ANGLER v4 prompt (sections 1–4, decisions already made, standing rules).

## Global Constraints

- `node --test tests/*.test.js` and `node tests/e2e.spec.js` pass; zero console errors, zero axe violations.
- `node tools/check-leniency.js` at zero name collisions.
- Push to `main` AND republish the artifact (slug 936624d1-86ff-4d8a-aa90-db1175cd0881) at the end; deploy `submit-dive` and `duel`.
- Ads and payments stay off; nothing added beyond the spec without permission; the VAPID private key is never read or committed.
- Takeover descent lasts 2,000–3,000 ms whatever the drop; no auto-advance anywhere; the next 25-s timer starts only after the tap.
- Duel: 2–8 players, 2 lives, hidden fuse 10–30 s drawn server-side, pass under 8 s resets to 8 s, pop ends the round, questions with 75+ answers only, no repeats by entity id.
- Bank: ≥75 answers per live question, tier floors (1 Hadal exactly, ≥3 Midnight, ≥8 Twilight, ≥12 Reef, ≥8 Bait Ball, ≥5 Tide Pool), every v4 answer has a `source`; bank never below 211 live questions; played days keep frozen sets.
- Autocorrect: typo budget 1/2/3 edits by 4–6 / 7–11 / 12+ letters; never fuzzy under 4 letters; `correction { from, to, accepted }` on the matcher result.

## Review Focus

1. A fuzzy hit whose canonical name is a plural/alias form — the corrected text must be the real spelling, not the normalised form (test: alias with an apostrophe, "Sowerby's beaked whale").
2. Reduced motion on the takeover — the button must still appear (after 600 ms) and the timer must not start until the tap.
3. Duel tick after a pop by a client that is behind — the reducer must ignore events with a stale round number (test: answer for round 1 after round 2 started → state unchanged).
4. A duel player leaving while holding the puffer — the puffer passes to the next living player with the 8-s floor.
5. The bank builder must never produce two entities with the same canonical name in one question (check-leniency stays at zero) and must not touch the answers of frozen days.

### Task 1: Autocorrect `correction` in the matcher (section 4)
Files: `shared/dive.js`, `tests/dive.test.js`, Edge Function copies via `tools/sync-shared.js`.
- `matchAnswer` returns `correction: { from, to, accepted: true }` when `via === 'fuzzy'` (to = the real spelling, proper case).
- A rejected guess within `fuzzyBudget + SUGGEST_EXTRA_DIST` returns `correction: { from, to, accepted: false, options: [{name, entityId}] }` (≤ 2 options); ambiguous short forms keep `ambiguous`.

### Task 2: Autocorrect UI (section 4)
Files: `game.js`, `styles.css`, `tests/e2e.spec.js`.
