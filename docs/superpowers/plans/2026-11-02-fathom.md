# FATHOM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static daily ocean-trivia website (Krillion loop, Wordle look) with a 120+ prompt curated answer bank, retention features, mock-able leaderboards, and flag-gated online/monetisation layers plus the Supabase server pieces.

**Architecture:** Pure static site (vanilla HTML/CSS/JS, hash routing) whose game logic lives in one shared file (`shared/dive.js`) that also runs in Node tests and Deno Edge Functions. Data is two JSON files compiled by `build.js` into browser globals. Everything online is behind flags that default off; `MOCK_ONLINE_DATA` renders demo boards.

**Tech Stack:** HTML/CSS/JS (no frameworks), Node 22 (`node --test`, build/validate scripts), Playwright (pre-installed) for e2e and icon rendering, Supabase (Postgres + Auth + Edge Functions in Deno), Stripe Checkout via Payment Links.

**Spec:** `docs/SPEC.md`

## Global Constraints

- 7 prompts per dive, 25 s per prompt, one submission per prompt, miss = 0.
- Tiers: tidepool 10 🐚, baitball 15 🐠, reef 30 🪸, twilight 60 🦑, midnight 85 🐙, hadal 100 🔱, miss ⬛.
- `METERS_PER_POINT = 10935 / 700`; depth = `Math.round(points * METERS_PER_POINT)`; perfect dive = exactly 10,935 m.
- Zones: Sunlight 0–200, Twilight 200–1,000, Midnight 1,000–4,000, Abyss 4,000–6,000, Hadal 6,000+.
- Gauge landmarks: 200, 1,000, 3,800 (Titanic), 4,000, 6,000, 8,336 (deepest fish filmed, snailfish 2023), 10,935 (Challenger Deep).
- Day boundary and countdown: America/New_York. Puzzle number counted from `LAUNCH_DATE`.
- ≥120 prompts, ≥25 answers each, exactly one hadal per prompt, every entity has one fact sentence.
- Matching: normalise (lowercase, trim, strip punctuation/accents, drop leading the/a/an, singularise simple plurals); exact first, else Levenshtein ≤1 (≤6 letters) / ≤2 (longer).
- Every parameter is a named constant at the top of its file. No external requests with all flags off. Original copy/art only. Relative paths only (GitHub Pages subpath + artifact origin).
- Files: index.html, styles.css, app.js, game.js, pages.js, storage.js, charts.js, entities.js, prompts.js, shared/dive.js, monetise.js, online.js, sw.js, manifest.json, build.js, data/*.json, privacy.html, terms.html, refunds.html, supabase/*, SETUP.md.

## Review Focus

1. Input "Great White Shark!" / " the  blue whale " / "sharks" must match (punctuation, spacing, article, plural) — test in Task 2.
2. A typo one letter off an alias of a *different* entity in the same prompt must resolve to the closest candidate, never to the wrong tier by accident — test in Task 2 (two candidates, distance 1 vs 2).
3. Day rollover while a dive is open: the dive keeps the prompt set it started with and saves under its own date — test in Task 4 (dive object carries `dayKey`).
4. localStorage unavailable (Safari private mode throws) — every storage call wrapped; game still playable — test in Task 4 (stub `localStorage` getter to throw).
5. Challenge URL with malformed seed/depth/tiers must fall back to a fresh seed without crashing — test in Task 2 (`parseChallenge`).

**Interfaces:**

- Validator rules: ids are slugs `^[a-z0-9]+(-[a-z0-9]+)*$`; kind ∈ {creature, plant, place, vessel, person}; tier ∈ six codes; ≥25 answers; exactly 1 hadal; no duplicate entity ids; within a prompt no two entities share a normalised name/alias; fact 20–220 chars, single sentence.

- [ ] Step 3: Implement `tools/validate-batch.js` exporting `validateBatch(batch, seeds, knownEntityIds) -> {ok, errors[]}`; CLI `node tools/validate-batch.js data/batches/X.json`.
- [ ] Step 4: Implement `tools/merge-batches.js` (union aliases by id, first fact wins, drop colliding aliases within a prompt with a warning) and `tools/validate-data.js` (same rules on merged set + every seed prompt present).

### Task 2: `shared/dive.js` core logic

**Files:**
- Create: `shared/dive.js` (UMD-style: sets `globalThis.FathomDive`, also `module.exports` when present)
- Test: `tests/dive.test.js`

**Interfaces (Produces):**
- `TIERS` ordered array `[{code, name, points, emoji}]`; `TIER_BY_CODE`; `METERS_PER_POINT`; `ZONES` `[{code,name,from,to,fact}]`; `LANDMARKS`.
- `normalise(str) -> string`
- `buildIndex(prompt, entitiesById) -> {exact: Map<norm, entityId>, candidates: [{norm, entityId}]}`
- `matchAnswer(typed, index) -> {entityId, tier, points, via:'exact'|'fuzzy'|null}` (null entityId when rejected)
- `depthFor(points) -> int`; `zoneFor(depth) -> zone`; `pointsToTierCode`
- `seededRng(seedString) -> () => float` (mulberry32 over fnv1a hash); `shuffle(array, rng)`
- `dayKey(date = new Date(), tz='America/New_York') -> 'YYYY-MM-DD'`; `dayIndex(dayKey, launch)`; `msUntilNextDay(tz)`
- `dailyPromptIds(dayKey, prompts, launchDate) -> string[7]` (cycle replay: per cycle shuffle by `fnv("cycle:"+n)`, greedy distinct groups, leftovers carried; then sort by difficulty asc, id asc)
- `freePromptIds(seed, prompts) -> string[7]`; `packPromptIds(pack, prompts)` (difficulty order only)
- `makeChallengeHash(seed, depth, tiers) -> '#/challenge/SEED-DEPTH-TTTTTTT'`; `parseChallenge(hash) -> {seed, depth, tiers} | null`
- `shareText({number, depth, percentile, tiers, siteUrl})`
- `scoreSubmission({promptIds, answers:[{typed, secondsUsed}]}, prompts, entitiesById) -> {points, depth, results[]}` (used by the Edge Function)

- [ ] Step 1: Write tests: normalise cases (Review Focus 1), exact vs fuzzy (Review Focus 2), depth 700 pts → 10935, zones at boundaries, deterministic daily set with distinct groups and ascending difficulty across 60 simulated days with no repeats inside a cycle, `parseChallenge` garbage → null (Review Focus 5), `scoreSubmission` equals summed tier points.
- [ ] Step 2: Run → FAIL. Step 3: Implement. Step 4: `node --test` → PASS. Step 5: Commit.
